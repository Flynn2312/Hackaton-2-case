## Коротко

Allur Twin — это живая модель сборочной линии завода в браузере. Завод работает всегда: симулятор на сервере
выпускает машины, изнашивает оборудование, ломает конвейер, повышает брак окраски и пишет всё это в базу.
Дашборд видит каждое событие через WebSocket в ту же секунду.

Когда что-то идёт не так, двойник не просто зажигает красную лампочку. Он прогоняет несколько вариантов
решения на копии завода на 3 часа вперёд, а Claude объясняет оператору, какой вариант лучше и почему.
Цифры считает модель завода, языковая модель их не придумывает.

```
Склад комплектующих → Сварка → Окраска → Сборка → Контроль качества → Склад готовой продукции
        4 узла          9 узлов   7 узлов   5 узлов       4 узла                 1 узел
```

## Как решение отвечает на кейс

| Требование кейса | Где в Allur Twin |
|---|---|
| Визуализация участков и оборудования | **Живой завод**: поток из шести участков, у каждого статус, буферы между ними и все узлы; карточка участка, паспорт оборудования |
| Мониторинг производительности, загрузки, простоев, качества | Строка KPI (OEE линии, выпуск за сутки, простой критичного оборудования, худший брак, прогноз месяца), выпуск по часам «план / факт» |
| Инциденты и отклонения | **Инциденты**: журнал с фильтром по участку, всплывающие уведомления, панель **Решения** |
| Аналитическая панель для руководителей | KPI с нормативами, узкое место линии, прогноз выполнения месячного плана, блок «Что требует внимания» |
| Прогноз простоев и узких мест с ИИ | **What-If** на копии завода, ИИ-варианты решения инцидентов, тренды износа и простоев, **ИИ Ассистент** |
| Режим, близкий к реальному времени | Непрерывный симулятор плюс WebSocket-поток: дашборд обновляется без перезагрузки |

## Что умеет

### Лендинг
Первое, что видит гость (`#/`). Коротко рассказывает о продукте и сразу показывает живой завод:
- **живая панель:** заводские часы, которые тикают с текущей скоростью симуляции, оборудование в работе,
  идущие простои, открытые и критичные инциденты;
- **проблема кейса в цифрах:** 55 минут простоя Конвейера-03, брак ЛКП 5,2% при норме 2%, OEE сварки 81%,
  4 800 машин за месяц при плане 5 500;
- **шесть участков** со статусами прямо из двойника;
- **карточки модулей:** каждая открывает свою вкладку дашборда (`#/app/whatif`, `#/app/log` и т. д.);
- **«Попробуйте сами»:** кнопки вызывают аварию в симуляции и переводят в дашборд, где её видно сразу;
- блоки про ИИ, экономический эффект и архитектуру.

Лендинг делает один лёгкий запрос раз в 15 секунд. Заодно он будит бесплатный инстанс Render, пока гость читает
страницу. Тяжёлые данные дашборда загружаются только при переходе в него.

### Живой завод
- Поток участков слева направо. У каждого участка главный показатель (OEE, брак или оборудование в работе)
  с нормативом, точки-узлы со статусами и подсказка, что не так.
- Между участками показаны **буферы**: сколько кузовов ждут следующий участок. На участке с минимальным OEE
  стоит метка **«узкое место»**.
- **Выпуск по часам**: столбцы «факт против плана» с цветом по выполнению.
- **Что требует внимания**: идущие аварии, оборудование с растущими простоями (с оценкой срока и вероятности),
  рост брака, узкое место. Для каждого пункта написано, что делать.
- Клик по участку открывает **боковую панель**: параметры процесса за сутки, тренд, узлы, кнопки «Смоделировать
  в What-If», «Инциденты участка», «Спросить ИИ ассистента».
- Клик по узлу открывает **паспорт оборудования**: статус, наработку, последний простой, расход лимита простоя
  и демо-телеметрию вибродиагностики по зонам ISO 10816.

### What-If: «что будет, если…»
Сценарный тренажёр на **копии живого завода**. Рычаги:
- внеплановый простой;
- загрузка линии;
- брак окраски;
- аварии Конвейера-03, Камеры-02, робота ABB;
- буфер перед сборкой;
- превентивное ТО в пересменку.

Есть быстрые сценарии: «Брак окраски», «Обрыв цепи (55 мин)», «Загрузка −15%», «Оптимальный».

По кнопке **«Спрогнозировать»** сервер берёт текущее состояние завода (износ, буферы, идущие простои, смену)
и прогоняет две копии на 8 часов работы линии: без изменений и со сценарием. Таких прогонов 6, в каждом
одинаковые случайные события, поэтому разница между копиями — это эффект решения, а не случайность.
Claude по этим цифрам пишет вывод: к чему приведёт сценарий, почему и как действовать.

### Инциденты и «Решения»
Симулятор порождает инциденты по правилам кейса: отказ оборудования, нехватка комплектующих, рост брака,
превышение лимита простоя. Серьёзный инцидент **ждёт решения оператора**:

1. Для каждого допустимого действия копия завода прогоняется на 3 часа вперёд. Считаются выпуск, простой,
   брак, OEE, затраты и эффект в тенге.
2. Claude выбирает два лучших действия и формулирует варианты **A** и **Б**. Третий вариант всегда
   «ничего не менять». Claude рекомендует один из трёх и объясняет выбор цифрами.
3. Панель **«Решения»** открывается сама. Оператор выбирает вариант, и он применяется в симуляции:
   аварийная бригада вдвое сокращает ремонт, перекалибровка снижает брак.
4. Если не выбрать вариант за 30 минут заводского времени, применяется «ничего не менять».

Журнал **Инцидентов** показывает весь жизненный цикл `open → in_progress → resolved → closed` и принятые решения.
Новые события приходят всплывающими уведомлениями; клик ведёт к участку или решению.

ИИ-решения можно выключить в панели симуляции. Тогда инциденты не ждут выбора, а запросов к Claude нет.

### ИИ Ассистент
Чат о заводе. Сервер собирает срез данных:
- живое состояние линии;
- сутки по участкам;
- 14 дней истории;
- простои по оборудованию;
- инциденты и решения;
- план месяца и нормативы.

Claude отвечает **только по этому срезу**. На вопросы не о заводе ассистент вежливо отказывает, а если данных
нет, так и говорит. Под ответом есть подсказки следующих вопросов. Если ассистента открыть из карточки участка,
он отвечает в контексте этого участка. Если ИИ недоступен, отвечают встроенные правила по данным дашборда.

### Панель симуляции
Справа в шапке:
- время завода и статус `LIVE`;
- скорость ×15 / ×30 / ×60 (по умолчанию 1 секунда равна 30 секундам завода);
- пауза;
- выключатель ИИ-решений;
- **«Вызвать событие»**: обрыв цепи Конвейера-03, рост брака ЛКП в Камере-02, столкновение робота ABB-04,
  нехватка комплектующих, нарушение техники безопасности.

Ночи и выходные симулятор пропускает.

## Как устроен симулятор

`backend/app/simulator/` — событийная модель линии. Она работает в фоне при старте API и пишет в Supabase:
- смены и планы;
- почасовую выработку и качество;
- простои с изменением статуса оборудования;
- инциденты.

- **Износ.** У каждого узла есть накопленный износ и своя скорость износа. Чем выше износ, тем чаще короткие
  остановки-предвестники, а при 100% случается тяжёлый отказ. Плановое ТО сбрасывает износ. Изношенная
  окрасочная камера повышает брак.
- **Поток.** Буферы между участками, нехватка кузовов ниже по линии, такт сборки.
- **Непрерывность.** Время завода переживает перезапуски, потому что состояние движка хранится в
  `simulator_state`. Генерирует только один инстанс: он держит аренду и шлёт heartbeat раз в 3 секунды.
  Если владелец пропал, другой инстанс подхватывает генерацию примерно через 20 секунд.
- **Прогнозы.** What-If и варианты решений используют тот же движок на копии состояния в памяти,
  без записи в БД.

## Эффект для бизнеса

Три рычага экономии и допущения, на которых построен расчёт (`ECON` в `front/allur-twin/src/lib/model.js`):

| Рычаг | Допущение | Цена |
|---|---|---|
| Предиктивное ТО | −30% внеплановых простоев | 85 000 ₸ за минуту простоя линии |
| Контроль параметров процесса | −50% брака и доработок | 120 000 ₸ за исправление кузова |
| Балансировка потока | 25% недовыпуска возвращается | 350 000 ₸ маржи с автомобиля |

Годовой эффект считается по фактическим простоям, браку и недовыпуску двойника за окно наблюдения
и пересчитывается на 250 рабочих дней.

**Пилот:**
- запуск за 4 недели на линиях окраски и сборки;
- оценка CAPEX — 85 млн ₸ (шлюзы OPC UA, датчики вибрации и температуры, интеграция);
- оценка OPEX — 20 млн ₸ в год.

**Внедрение без остановки завода.** Телеметрия снимается поверх существующей автоматики (Siemens S7-1500,
роботы Fanuc/ABB) по OPC UA / MQTT. Управляющую логику ПЛК менять не нужно: на пилоте реальные датчики
заменяют симулятор, а дашборд, прогнозы и ИИ остаются теми же.

## Запуск локально

### 1. База данных
В Supabase → SQL Editor выполнить по порядку:
- `backend/supabase/migrations/001_init_schema.sql`;
- `002_simulator.sql`;
- `003_incident_decisions.sql`.

### 2. Backend
```bash
cd backend
python -m venv .venv
.venv\Scripts\activate            # Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env              # SUPABASE_*, DATABASE_URL, ANTHROPIC_API_KEY
python -m scripts.seed            # история 01.07–05.10.2026 с данными кейса
uvicorn app.main:app --reload --port 8000
```
- Swagger: http://localhost:8000/docs
- Если параллельно работает задеплоенный бэкенд, поставьте `SIMULATOR_ENABLED=false`, чтобы локальный
  экземпляр не перехватывал генерацию.
- Без `ANTHROPIC_API_KEY` всё работает, но варианты и тексты строит резервный алгоритм.

### 3. Frontend
```bash
cd front/allur-twin
npm install
npm run dev
```
- Адрес: http://localhost:5173
- Адрес API задаётся в `.env` (`VITE_API_URL`). Для локального бэкенда создайте `.env.development.local`
  с `VITE_API_URL=http://127.0.0.1:8000`.

## Демо за 3 минуты

1. Откройте лендинг: завод уже работает, часы тикают, видны статусы участков.
2. Нажмите **«Обрыв цепи Конвейера-03»** в блоке «Попробуйте сами». Откроется дашборд: сборка краснеет,
   буфер перед ней растёт, приходит уведомление.
3. Через 10–25 секунд откроется панель **«Решения»**: три варианта с прогнозом выпуска, простоя и денег
   и рекомендация ИИ. Выберите вариант и посмотрите, как линия восстанавливается.
4. Перейдите в **What-If**. Выберите «Брак окраски», нажмите «Спрогнозировать» и сравните 8 часов
   «как есть» и со сценарием.
5. Спросите **ИИ Ассистента**: «Выполним ли месячный план?»
